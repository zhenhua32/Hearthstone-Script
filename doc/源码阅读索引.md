## 3. 运行时关键对象

| 对象 | 生命周期 | 线程/使用注意 |
|---|---|---|
| PauseStatus | 程序级，全局 | JavaFX 属性；后台切换使用 asyncSetPause |
| Mode | 工作期间持续 | 模式变化排队，进入/离开动作异步执行 |
| WAR | 多局复用，局间由 WarEx 重置 | Power.log、策略、MCTS 都会访问 |
| WarEx | 一局一轮 | 负责统计、胜负、经验和清理 |
| PluginManager | 启动时加载，开关改变时重建 | ServiceLoader、ClassLoader 和版本覆盖 |
| CardActionManager | 插件加载后构建 | 按策略 pluginId 建立 LikeTrie |
| DeckStrategyManager | 插件加载后构建 | 过滤当前运行模式并持久化默认策略 |
| TaskManager | 应用全生命周期 | 暂停时关闭已登记的 Closable 任务 |
| LogFileManager | 内存日志模式 | 按文件名缓存 MemoryLogFile 通道 |

## 4. 事件顺序索引

### 4.1 从启动到第一局

~~~text
MainKt
  → JavaFX MainApplication
  → preInit
  → InitializerConfig
  → Core / PauseStatus
  → StarterConfig
  → Battle.net
  → Hearthstone
  → DLL 注入与日志通道
  → ScreenLogListener 识别界面
  → HubModeStrategy 进入目标运行模式
  → TournamentModeStrategy 或 AdventureModeStrategy
  → Power.log CREATE_GAME
  → WarEx.startWar
~~~

### 4.2 从 Power.log 到动作

~~~text
PowerLogListener
  → 当前 WarPhaseEnum 对应 PhaseStrategy
  → PowerLogUtil 解析 entity/tag/block
  → WAR.cardMap、Player、Area、Card 状态变化
  → GameTurnPhaseStrategy / ReplaceCardPhaseStrategy
  → DeckStrategyActuator
  → 当前 DeckStrategy
  → CardAction / MCTS / 权重组合
  → GameUtil / CSystemDll 真实点击
~~~

### 4.3 一局结束

~~~text
Power.log LOST/WON/CONCEDED 或结束实体
  → GameOverPhaseStrategy
  → WarEx.endWar
  → StatisticsListener 写入 statistics.db
  → 清理解析动作和监听任务
  → 返回 Hub / 重新匹配 / 按工作时间暂停
~~~

## 7. 阅读时应优先确认的事实

1. 当前运行目录是否确实是程序根目录。
2. 当前构建是 JVM 还是 Native。
3. 游戏日志使用 DISK 还是 MEMORY。
4. 当前 Mode 与 WarPhase 是否一致；两者不是同一个状态机。
5. 当前策略的 pluginId 是否决定了卡牌动作可见范围。
6. 卡牌是走自动文本解析动作、基础插件手写动作，还是默认动作。
7. MCTS/权重策略是否在模拟模型上产生了真实可执行动作。
8. 工作时间规则是否覆盖了默认策略、运行模式和卡组位置。
9. Power.log 是否已打开 FilePrinting、Verbose 和足够的日志大小。
10. 更新时是否需要保留 config、data 和外部插件。
